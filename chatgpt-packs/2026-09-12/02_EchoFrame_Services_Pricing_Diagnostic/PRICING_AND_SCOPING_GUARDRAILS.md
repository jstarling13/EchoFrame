# EchoFrame Pricing & Scoping Guardrails

## Current Price
$40/hour for professional services.

This document does not change that rate.

## Additional Charges
- travel fee quoted before booking
- $50/day onsite food stipend
- third-party software/API costs only when disclosed and approved

## Principle
Hourly pricing should not mean undefined scope.

Every engagement should still state:
- desired outcome
- included workflows
- excluded workflows
- assumptions
- access required
- client responsibilities
- expected range of hours when reasonably estimable
- approval point before materially exceeding the range

## Recommended Estimate Format
Use ranges instead of false precision.

Example:
**Estimated effort: 12–18 hours**
If work is likely to exceed 18 hours, pause and obtain approval before continuing unless the agreement says otherwise.

## Change Control
A scope change exists when:
- new workflow added
- new entity/location added
- new integration added
- client changes source system
- data quality materially differs from assumptions
- compliance/security requirement adds work
- client requests custom reporting beyond agreed output

Document the change and update expected hours.

## Minimum Economic Review
Before accepting work, estimate:
- expected hours
- travel cost/time
- third-party tool cost
- support burden
- implementation risk
- likelihood of additional unpaid troubleshooting

A project can be strategically useful even if small, but it should be accepted intentionally.

## Module Base Fees
The Hendizadeh proposal used base fees for certain modules plus hourly overage.

This pack does not standardize those fees because Jacob has not approved them as a general pricing model.

Recommendation:
Keep the current public model hourly-only. Use module minimums or base fees only as internal quoting tools if Jacob later approves them.

## Retainers
Do not promise unlimited support.

If ongoing work becomes frequent, use one of:
- normal hourly billing
- prepaid block of hours
- defined monthly office-hours/support allocation

Do not adopt a fixed retainer until usage data exists.
