# EchoFrame Discovery & Diagnostic Model

## Recommended Commercial Structure

### Step 1 — Free Fit Conversation
Purpose:
Determine whether the problem is real, whether EchoFrame is appropriate, and whether the buyer can support implementation.

Recommended length:
20–30 minutes.

No deep process mapping.
No custom solution design.
No unpaid technical architecture.

### Step 2 — Paid Discovery / Diagnostic When Needed
Billed at the standard $40/hour rate.

Use when:
- workflow is complex
- multiple entities/systems are involved
- ROI cannot be estimated responsibly from the initial call
- onsite observation is needed
- data access must be reviewed
- implementation scope is uncertain

For simple jobs, discovery can be incorporated directly into the first paid work block instead of becoming a separate product.

## Diagnostic Deliverables
Depending on scope:
1. Current-state workflow map
2. Pain-point and exception list
3. Systems / data-source inventory
4. Automation feasibility assessment
5. Risk and human-approval points
6. Opportunity list
7. Prioritization
8. Rough effort estimate
9. Value / ROI range
10. Recommended first implementation
11. Items explicitly not recommended for automation

## Diagnostic Categories

### Workflow
- frequency
- volume
- people involved
- handoffs
- repeated entry
- waiting time
- exceptions
- error/rework rate

### Systems
- current software
- API availability
- export/import options
- permissions
- integration constraints
- data ownership

### Data
- source of truth
- quality
- sensitivity
- retention
- structured vs unstructured

### Economics
- labor time
- outside vendor cost
- backlog cost
- missed revenue / response delay
- implementation effort
- expected maintenance

### Risk
- accounting judgment
- payment authority
- PHI/PII
- legal implications
- employment decisions
- human review requirements
- auditability

## Opportunity Scoring
Score each candidate 1–5 on:
- frequency
- labor burden
- process stability
- data availability
- error cost
- implementation feasibility
- user adoption likelihood
- risk / control complexity

Do not use one simplistic total score mechanically.
High-risk items can be rejected even if economic value is high.

## Output Format
### Recommended First
Workflow(s) suitable for immediate improvement.

### Later
Worth revisiting after foundational work.

### Do Not Automate
Poor economics, unstable process, unsupported risk, or existing tool already solves it.

## Conversion to Implementation
The diagnostic should end with:
- objective
- scope
- assumptions
- data/system access
- estimated hours or range
- travel requirement
- success measures
- client responsibilities
- next approval point
