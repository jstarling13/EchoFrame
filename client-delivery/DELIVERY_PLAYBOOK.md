# EchoFrame Delivery Playbook

## Phase 1 — Observe
Goal:
Understand the real workflow.

Outputs:
- workflow map
- systems
- actors
- exceptions
- controls

## Phase 2 — Weigh
Goal:
Decide whether automation is worth doing.

Outputs:
- pain/economic estimate
- feasibility
- risk
- priority

## Phase 3 — Navigate
Goal:
Choose the implementation path.

Outputs:
- architecture
- tool selection
- human approval design
- scope
- success metrics

## Phase 4 — Engineer
Goal:
Build the smallest useful solution.

Rules:
- test with sample data first
- separate routine path from exceptions
- preserve source-of-truth systems
- avoid unnecessary new software
- document assumptions
- log important actions where practical

## Phase 5 — Demonstrate & Transfer
Goal:
Make the client capable of using and owning the system.

Outputs:
- user testing
- training
- SOP
- access transfer
- support boundary
- results baseline
- backlog for later improvements

## Implementation Discipline
Every project should have:
- one named objective
- one named owner
- one measurable result
- explicit out-of-scope items
- explicit human-review points
- a stop condition if economics or risk change

## Post-Launch
30-day or agreed review:
- usage
- failures
- exceptions
- time saved/capacity created
- user feedback
- security/access changes
- whether further work is justified
